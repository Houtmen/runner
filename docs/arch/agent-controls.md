# Visual agent controls

Open Settings → Agent controls. This page uses the same daemon operations as the CLI; it does not start or resume agents automatically. Refresh reloads the server state and form values.

- **Parallel sessions:** view reserved capacity and save a positive maximum, or leave the field blank for unlimited. The saved value takes precedence over RUNNER_MAX_SESSIONS after daemon restart. Lowering it preserves running sessions and blocks further admission until capacity is available. Failed storage leaves the live limit unchanged. Saves are serialized without holding the admission mutex during database IO.
- **Role settings:** choose a role, browse/save an absolute Codex home, and configure an ordered model list. A blank home inherits Runner's daemon-wide home; overrides apply to new sessions and preserve other environment variables. The daemon-wide home shown on the page still controls Settings catalogs and global usage. Authentication is not copied. Model names are one per line or comma-separated; saving makes the first the role's primary model. Clearing the list preserves the existing single default.
- **Session model:** choose an unarchived session. Stop a running session explicitly, select a configured alternative, then resume through the existing chat controls. Runtime-only sessions need a role to configure alternatives. Model selection retains the native ID/arguments/environment/cwd. For Codex, use the file picker to synchronize an owned rollout after a native model change. The dialog result is discarded if the selected session changed while it was open.
- **Mission review:** select a running mission and set an immutable repair budget, including zero. The strict log replay displays the counter and open/complete/exhausted state; damaged logs fail closed. A budget counts typed repair requests, not free-text or internal CLI subagents, and does not terminate running processes.

Selectors and inputs are disabled while their data loads or an operation is pending. Late replies are discarded by generation, and errors remain visible. Backend checks remain authoritative if another window/client changes state. Persisted review budgets are read-only; a new mission is required for a different budget.

The design issue and mockup are in Houtmen/runner#8. Native mock-client UI tests verify loading and writes for the limit, isolated home and explicit model choice with native ID preservation; input/eligibility tests cover invalid limits, ordering and running sessions. Backend tests cover restart, failed storage, environment preservation, archived filtering and strict review replay. Native Windows/macOS CI and the relocated Windows package startup check remain required. Real subscribed-agent and physical-host before/after screenshots are separate manual validation, not implied by mock tests.
